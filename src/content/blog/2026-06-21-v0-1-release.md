First runnable cut of the framework. Four tools, two agents,
a sqlite-backed finding store, and a CLI. 41 tests, 100% green.

## What shipped

The framework follows a four-layer architecture: _Tools → Tasks →
Pipelines → Agents_. Every layer is local-first, human-in-the-loop,
provenance-aware, and refuses to load a tool whose legal note is
missing.

- **Tools (4):** `web_search` (DuckDuckGo HTML), `web_fetch` (httpx + readability, with SSRF allowlist), `paper_lookup` (arXiv public API), `whois` (system whois).
- **Tasks (1):** `search_papers` — wraps `paper_lookup`, scores by token overlap.
- **Pipelines:** declared DAGs with wall-clock + call budget enforcement.
- **Agents (2):** `LiteratureResearchAgent` (academic lane), `DomainReconAgent` (OSINT sub-lane).
- **Storage:** sqlite-backed finding store, two write APIs (object or dict).
- **CLI:** `mad-river agent`, `mad-river run` (stub), `mad-river inspect`.

## The honest retrospective

The plan was reviewed twice before any code was written. The
first pass was self-review (hermes, the writing agent). It
caught 5 issues. The second pass used a different model
(OpenCode with `nemotron-3-ultra-free`) to avoid
self-review bias. It caught **10 more**, including
two critical test-fixture bugs that would have failed the very
first `pytest` run.

The pattern: _the same agent that writes a plan cannot
reliably catch its own test-fixture mistakes_.
A different-model review is non-negotiable for plans of this
size. We burned 5 minutes of plan-time and saved at least 30
minutes of execution-time debugging. Adopt it.

## What's next

**v0.2** brings real-LLM synthesis (local Ollama
default, cloud fallback), a YAML pipeline runner, and a
`parent_id` field on Findings for a complete
provenance chain. Then the hosted surface: a web UI on top
of the runtime.

The framework stays MIT forever. The interesting bits — paid
data sources, customer UX — live in private repos and ship
as managed services later.
